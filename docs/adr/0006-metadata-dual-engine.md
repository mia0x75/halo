# ADR 0006: 元数据库双引擎（MySQL + PostgreSQL 并行包）

## 状态

已接受

## 背景

战略要求元数据库支持 MySQL 与 PostgreSQL，但首版只有
`internal/repository/mysql`。需要第二引擎，且保持同一套
`domain` 仓储契约、同一套 service/GraphQL，不分叉业务逻辑。

## 决策

1. **并行包**：新增 `internal/repository/postgres`（独立 sqlc 生成 +
   手写 repo），与 mysql 包实现同一套 `domain` 接口；
   `database.driver`（`mysql` 缺省 / `postgres`）在
   `internal/app` 选择，禁止跨包共享查询与转换代码。
2. **驱动**：`database/sql` + `github.com/jackc/pgx/v5/stdlib`
  （`db.go` blank import，`sqlx.Open("pgx", ...)`），无 CGO，单二进制不受影响。
3. **类型映射**（MySQL→PG）：`INT UNSIGNED`→`BIGINT`；
   `INT UNSIGNED AUTO_INCREMENT`→`BIGINT GENERATED BY DEFAULT AS IDENTITY`；
   `TINYINT[ UNSIGNED]`→`SMALLINT`；`SMALLINT UNSIGNED`→`INTEGER`；
   `BIGINT UNSIGNED`→`NUMERIC(20,0)`；`VARBINARY(n)`→`BYTEA`；
   `DECIMAL(18,4)`→`NUMERIC(18,4)`；`DATETIME`→`TIMESTAMPTZ`；
   变长 `CHAR`→`VARCHAR`（PG 的 `CHAR(n)` 会补空格，参考
   rule 短名测试失败教训）；保留字双引号。
4. **时间写入**：两引擎各用方言——MySQL 靠列的
   `ON UPDATE CURRENT_TIMESTAMP`，PG 在 UPDATE 语句里显式
   `update_at = NOW()`；INSERT 都省略时间列（靠 DEFAULT）。
5. **取号**：PG 无 `LastInsertId`，`Create*` 用
   `INSERT ... RETURNING <id>`（sqlc `:one`），domain 接口不变。
6. **错误映射**：PG 唯一冲突 `SQLSTATE 23505`→`domain.ErrConflict`
  （对 MySQL 1062），`sql.ErrNoRows`→`domain.ErrNotFound` 不变。

## 后果

- `scripts/halodb_schema_postgres.sql` / `scripts/halodb_seed_postgres.sql` /
  `migrations/postgres/0001_init.sql` 为 PG 建库与种子数据来源；
  seed 用 `to_timestamp()`/`NOW()`，identity 列首值写 `DEFAULT`，
  显式 ID 的表末尾 `setval` 校准序列。
- PG repo 测试 19 项直连 PG 16 实测通过（`HALO_TEST_PG_DSN`，
  回退 `bin/config.postgresql.json`，无库则 skip）。
- `g.DatabaseConfig.Driver` 新增；旧配置缺省走 MySQL，行为不变。
