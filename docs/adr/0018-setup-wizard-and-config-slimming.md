# ADR 0018: 首次安装引导与配置瘦身

## 状态

已接受

## 背景

两件事叠在一起：

1. 配置文件里 `mail` 段与 `mm_options` 里的邮件选项是同一份配置的两个来源，
   `backup` 段则全项目零引用；密码还留在配置文件的明文里。
2. 新装一台机器没有任何配置文件，服务器直接退出，管理员要手工准备
   `cfg.json`（含数据库连接串与 JWT 密钥）才能启动，种子里的初始账号还是
   固定密码 `Admin123#!`。

## 决策

**配置文件只保留启动必须的项，其余走数据库；首次安装由 /welcome 向导完成。**

1. **配置瘦身**：删除 `mail` 段与 `backup` 段。SMTP 配置只以 `mm_options`
   为准（ADR 0017 的延续），备份连接段没有实现，直接去掉。
2. **初始化模式**：启动时若缺 `database.addr` 或 `secret`，服务器进入初始化
   模式，只提供 `GET /api/setup/status`、`POST /api/setup` 与前端静态资源；
   GraphQL 接口此时不存在。初始化完成后这两个接口返回 404。
3. **向导表单**：元数据库类型与连接串、连接池参数、JWT 密钥、加密密钥、
   初始管理员邮箱与密码。密钥提供一键生成。
4. **初始化流程**：连库 → 执行迁移 → 写入基础数据（角色、规则、模板）→
   写配置文件（原子替换，权限 0600）→ 建立初始管理员 → 启动应用并热切换
   路由，**不需要重启**。种子里的 Root 账号被改写为向导填写的邮箱与密码，
   固定密码不再存在。
5. **基础数据来源**：`scripts/halodb_seed_*.sql` 内嵌进二进制，由向导执行；
   与迁移重复的选项行（保留期、邮件）已从种子脚本删除。

## 后果

正面：

- 新装只需要能访问端口，不需要预备配置文件；
- 配置文件里不再有 SMTP 密码，数据库口令只落在一处；
- 固定默认密码账号在初始化后不复存在。

负面：

- 系统未配置时，初始化接口对所有能访问端口的人开放，部署时应限制来源；
- 基础数据脚本与迁移脚本必须手工保持不重叠，否则初始化会失败；
- 向导依赖配置文件目录可写，否则写配置这一步会失败。

## 后续

- 若要支持多实例部署，初始化接口需要额外的来源限制或一次性令牌；
- 备份配置（`backup` 段）若要实现，选项名沿用 `backup.*` 前缀。
